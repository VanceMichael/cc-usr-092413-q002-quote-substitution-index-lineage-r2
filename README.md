# 采价缺货替代与指数回溯

记录采价事件、替代决定与指数版本，回答“某个观察日到底采用了哪条价格”，
并在进程重启后继续隔离处理、到期替代和重算任务。

## 开发命令

- 安装依赖：`npm ci`
- 运行测试：`npm test`
- 编译或构建检查：`npm run build`
- 启动服务：`npm start`（默认 `DATA_FILE=/data/state.json`，可用环境变量覆盖）

测试和构建只使用仓库内数据，不需要连接外部业务服务。

## 领域规则

- **幂等接收**：原始报价、缺货、恢复、质量变更均按 `(source_id, source_seq)` 幂等；
  重复报文直接返回 `duplicate`。
- **同标识异文隔离**：同一 `event_id` 报文内容哈希不一致，或不同事件复用来源序号，
  进入隔离队列并产生 `quarantine_resolve` 待办；人工可 `accept`（可附更正报文）或 `reject`。
- **替代评估**：采价点失效后按生效中的规则版本挑选候选
  （同规格同地区 → 同规格相邻地区 → 同质量同地区），逐候选保存合格性与未采用原因；
  候选报价超龄、候选自身缺货、质量差异超上限都会落选。没有合格候选时**保留缺口**，
  不沿用过期价格。
- **替代决定（审批后生效）**：固定失效点的商品规格、地区、门店层级，记录候选质量差异、
  有效区间 `[valid_from, valid_to)` 与审批依据；批准时做防环与链长校验，任何情况下不可绕过。
  恢复事件只关闭有效区间；**跨日恢复不能反向改写已发布观察值**。替代到期后自动失效。
- **指数与重算**：观察值按规则版本聚合（几何/算术平均），开放期间内可重算并保留完整版本链；
  一旦发布即冻结。重算采用修订号乐观并发——提交时若有迟到事件推进了修订号，旧结果被阻止回写，
  任务自动重试。
- **规则更正**：只重算仍开放的期间；已发布期间保留旧值、新值、差异和批准关系，不改写。
- **重启恢复**：状态以原子写落盘；任务（隔离跟进、到期替代、开放期间重算）持久化，
  启动时与定时 tick 继续执行。
- **时刻溯源**：`GET /v1/trace` 按任一观察时刻还原原始事件、替代路径（含固定要素与审批依据）、
  采用的规则版本以及最终进入指数的数值与逐点位贡献。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/v1/events` | 接收采价事件（幂等/隔离） |
| GET  | `/v1/events/:id` | 查询事件接收记录 |
| POST | `/v1/points` | 登记采价点档案（规格/地区/层级/质量等级） |
| POST | `/v1/policies` | 登记新规则版本（按生效时间选用） |
| GET  | `/v1/quarantine` | 隔离队列 |
| POST | `/v1/quarantine/:id/resolve` | 隔离处置（accept/reject） |
| POST | `/v1/substitutions/evaluate` | 触发候选评估 |
| GET  | `/v1/evaluations/:id` | 候选与未采用原因 |
| POST | `/v1/evaluations/:id/approve` | 批准替代（basis 与有效区间必填） |
| POST | `/v1/index/recompute` | 重算开放期间 |
| POST | `/v1/index/publish` | 发布观察值（随后冻结） |
| POST | `/v1/corrections` `/v1/corrections/:id/approve` | 规则更正与批准 |
| GET  | `/v1/trace?product_id=&region=&point_id=&at_ms=` | 任一观察时刻溯源 |
| GET/POST | `/v1/tasks` `/v1/tasks/tick` | 任务台账与手动推进 |
